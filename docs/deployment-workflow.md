# 流程编排

入口：**设置 → 流程编排**。配置全局生效，使用现有设置、执行记录及后台任务表，不另建流程专用表。

## 使用

- 节点可在画布上任意拖放，**坐标只影响布局，不决定执行顺序**。空白处平移，滚轮或双指缩放；选中节点后方向键移动位置，Shift + 方向键大步移动。
- 从节点下方输出点拖线到另一节点上方输入点，也可依次点击/触摸两个连接点；键盘 Tab 聚焦连接点后回车连接。连线可跨位置自由绘制，鼠标点击或键盘选中线后按 Delete / Backspace、或在右侧「删除连线」。Escape 取消未完成的连线/拖动。
- 连线表达前置依赖，按拓扑层生成执行轮次，每层最多 4 个节点；允许稀疏连线、跨层依赖和不同长度的分支。每轮全部节点与后台任务完成后才进入下一轮，所有分支最终连接到唯一出口。闭环或断开的连线可以留在草稿中，但必须修正后才能保存。
- 「撤销 / 重做」恢复单次编辑，也支持 Ctrl / Cmd + Z、Ctrl + Y / Cmd + Shift + Z（文本框内保留原生文本撤销）；「自动整理」只调整位置，不修改连线。右侧「快捷编排」可将节点加入并行组或拆出独立 turn，「提前一轮 / 延后一轮」修改连接关系；使用这些快捷操作会重建连接，拓扑未修正时不可用。
- 有前后依赖的内置节点不能并行；确认整合包与最终验证各自独占一个 turn。禁用分支不执行，其余分支仍必须汇合。无依赖不等于没有副作用冲突，不能并发写同一文件/配置。
- 右侧编辑步骤名称和 Agent 执行指令；自定义卡片可直接点击「关闭 / 启用」，也可使用右侧开关。关闭后节点和连线保留，步骤不参与执行及提示词；支持撤销、重做，保存后生效。最多 40 个步骤。
- 新建服务端时后端自动套用内置 reference MCDReforged 模板（含插件/配置与 `server/`），不再占用流程步骤，手动创建与全局 Agent 创建行为一致。模板复制失败时创建失败，清理本次新目录，不留下半初始化实例；创建本身不安装 Java/Python、不启动 Minecraft。已有实例不会批量覆盖，旧实例确实缺少模板时由 Agent 检查后以不覆盖方式补齐。
- 内置 7 个步骤不可移除/禁用，保留必要技术检查；执行顺序由连线决定，可自由调整轮次，例如将内置 Python 准备提前。确认整合包固定为首个启用步骤，最终验证固定为最后一个启用步骤。
- 默认编排：确认整合包 → 获取服务端包到槽位、检查 Java 版本依赖、配置内置 Python 并行 → 还原到 server 目录并安装 Loader、配置 MCDReforged 并行 → 最终验证。还原阶段使用已检查的 Java 完成 Loader 安装和布局检查，不再安排单独的直启验证。最终验证将服务端启动命令写入 MCDR `start_command`，再切换 `startupCommand={python} -m mcdreforged` 并验证。
- 最终验证启动服务端后必须调用 `wait_for_server_startup`。该工具监听当前实例控制台，阻塞直到出现 Minecraft 的 `Done (...)!` 启动完成标记；服务端提前退出、Agent 取消或达到超时会立即返回错误。禁止用 `sleep`、固定时长等待或 Shell 轮询替代。
- 每次操作结束自动检查：入口/出口是否唯一、有无闭环或断开、并行分支是否收束、必需阶段和提示词；也可手动「检查流程」。不合法的操作保留在草稿中，画布高亮相关节点和连线，显示具体问题，禁止保存和生成误导预览；不会弹回或静默修复。不再强制「某步骤必须位于另一步骤之后」，内置步骤之间的固定前置连线可以按需重连。
- 提示框、保存门禁和「Agent 会看到什么？」预览共用同一份校验函数，不存在前端与后端两套规则；后端直接请求也不能绕过。校验失败不会改变已保存的配置或正在运行的部署。
- 「默认编排」只修改草稿，点击「保存编排」才写入数据库；「撤销更改」恢复最近保存的版本。
- 草稿在切换设置板块时保留；未保存时离开/刷新浏览器会提示。保存失败保留草稿，可重试。设置页与当前设置标签会在刷新后恢复。

## Agent 实际输入

System 消息按以下顺序组装：

1. 实例独立基础 Prompt（若启用），否则全局基础 Prompt；
2. 已启用 Skill 的内容；
3. **当前部署流程（流程编排 · 权威配置）**；
4. 运行时工具事实与失败恢复规则。

当前实例目录、版本、内存、文件、上传及槽位等运行事实通过独立的 runtime-context 消息附加，之后还有对话历史和结构化工具调用结果。工具定义随请求传递，并非全部打印在 System Prompt 中。

「Agent 会看到什么？」提供两个服务端预览：

- **流程提示词**：只显示流程编译的部分；
- **完整默认 System Prompt**：实际默认 System 消息全文。实例独立 Prompt 会替换第一部分，API 可指定 `serverId` 预览该实例。

预览与执行调用相同组装函数；测试捕获模型请求并逐字比对，而非用前端另写模板模拟。预览无模型调用、无持久化。禁用的自定义步骤不会出现在流程提示词或进度工具的 `stepId` 枚举中。

例如将 Python 准备提前，并在最终验证前增加「备份检查」，Agent 会收到：

```text
# 当前部署流程（流程编排 · 权威配置）
...
## 执行顺序
1. 确认整合包 [identify_modpack]
2. 配置内置 Python [configure_python]
3. 获取服务端包到槽位 [prepare_server_slot]
4. 检查 Java 版本依赖 [check_java_dependencies]
5. 还原到 server 目录 [extract_to_workspace]
6. 配置 MCDReforged [configure_mcdr]
7. 备份检查 [custom_...]
8. 最终验证 [final_mcdr_test]

按上述顺序执行；每阶段开始、完成或失败都调用
update_agent_workflow_progress(stepId, status, progress, detail)。

## 8. 备份检查
stepId: custom_...

用户填写的执行指令原文。
```

每个启用步骤都有同样的独立章节。编辑内置指令时，会同时附加不可取消的必要技术检查。流程明确覆盖旧 Prompt、Skill 或历史中的固定顺序，但不取消用户确认、凭据检查、目录隔离和真实日志验证。

## Turn 执行和并行收束

- 完整部署由实例 Agent 调用 `begin_deployment_workflow` 启动。查询、排错、安装单个模组仍是普通对话，不强制启动完整部署。全局 Agent 先交接给实例。
- 一个串行节点对应一个完整模型/工具对话 turn；同一并行组的全部节点共用一个 turn，不启动多个模型会话。所有轮次共享同一配置快照与追加式会话历史，System/tools 前缀稳定；每轮的节点清单以追加调度消息提供。
- 并行来自已有 `run_shell_command` / `install_java_version` 的 `background=true`。其他工具仍阻塞、串行，不能因为处于并行组就任意后台化。Agent 仍负责选择安全、不冲突的具体操作。
- 流程内工具必须携带 `workflowStepId`，进度工具使用 `stepId`；服务端拒绝跨轮 ID。槽位获取、Java 安装、Loader 安装、Python 配置等专用部署工具还有固定节点归属校验。确认轮只允许只读与用户交互，必须有真实 `ask_user` 回答才能完成。
- 仅后台回执、自然语言完成回复不构成成功：调度器等待本轮全部工具结束（事件驱动，无轮询）、将结果送回同一个 turn，并检查本轮每个启用节点均为 completed。后台失败/取消/中断、未读取结果或节点未完成会阻止下一轮；相同操作的成功重试可替代其失败记录。
- 独立分支可以先完成，无需等待同组其他分支；但分支自身的工具和后台结果必须完成核验。任何一个分支或后台任务未完成，整组都不能推进。
- 本轮真正完成后，后端持久化独立的下一 turn 并自动启动；前端在轮次间保持忙状态，只在最终完成/失败/取消时收到整体 done。并行轮的分支与当前 turn 会显示在部署进度中。
- 失败后恢复同一 turn；取消会停止自动推进。重启不会自动重放结果不确定的工具；明确未启动的持久化下一轮可安全调度一次，已经运行的轮次需要恢复。晚到的后台结果不会单独开启绕过门禁的对话。

**范围：支持单入口、单出口 DAG，按拓扑层调度 turn，每轮最多 4 个节点；不启动多个模型并发执行。** 后端约束轮次和后台任务收束；节点技术工作、Shell 内操作是否正确及成功证据仍须模型结合真实结果判断，不能把任意自然语言或 Shell 语义当成形式化证明。

## 持久化和执行一致性

- 配置保存在现有 `app_settings` 的 `deployment_workflow_v1`，JSON schema 版本为 `1`。
- 可选 `canvas` 持久化节点坐标和显式有向连线；保存时按合法连线生成执行节点顺序和并行组，坐标不会影响 Prompt 或 turn。旧配置没有画布字段时，编辑器根据原有串行/相邻并行组生成初始连线和布局，无需预先写库；下一次显式保存才持久化。
- 无设置时使用内置默认值；损坏或不兼容设置回退到经过校验的默认流程。
- 旧版包含 `apply_mcdr_template` 的保存配置读取时自动兼容：移除模板步骤，在还原步骤之前插入 Java 版本依赖检查，保留其他步骤的相对顺序、名称、自定义指令和禁用状态；仅未编辑的旧内置默认指令更新为新默认值。读取/预览不写数据库，下次显式保存时持久化升级。当前 API 不接受重新保存废弃模板步骤。
- 每个新部署流程固定一份配置快照，沿用到后续所有 turn，连同执行记录持久化。修改设置不会在流程中途改变顺序。
- 失败后恢复、进程重启后恢复继续使用原快照及已有 System 消息；新任务才使用最新保存配置。
- 进度工具的步骤 ID、名称和顺序与快照一致；进度按真实上报累积，不因跳到后一个阶段而把之前阶段伪标为完成。阶段/总进度快照随执行记录保存。
- 内置 Skill 不再定义另一套固定顺序；原有工具技术说明保留，统一引用流程编排。

## API

- `GET /api/settings/deployment-workflow`：保存配置、默认配置、阶段依赖和编译后的流程 Prompt。
- `PUT /api/settings/deployment-workflow`：校验并保存 `{ version: 1, steps: [{ id, label, prompt, enabled, parallelGroup? }], canvas?: { positions: { [stepId]: { x, y } }, edges: [{ id, from, to }] } }`。有 `canvas` 时以连线为准，服务端规范化 `steps` 顺序与 `parallelGroup`；无 `canvas` 时兼容原有相邻同 `parallelGroup` 的闭合并行组与串行配置。最多 40 节点、160 连线，坐标为 ±10000 内有限数值。
- `POST /api/settings/deployment-workflow/reset`：持久化恢复默认值。
- `POST /api/settings/deployment-workflow/preview`：`{ workflow, serverId? }`，返回 `{ prompt, effectivePrompt }`，不保存。

所有接口继承现有身份验证；无效配置返回 HTTP 400。

画布的 SVG、Pointer Capture、平移、锚点缩放和双指手势设计适配自 `~/workspaces/ChatHub-Server/web/app.js` 中的 topology 实现，未引入额外画布依赖。
